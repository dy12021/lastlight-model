# LAST LIGHT MODEL：维护一个自己

剧情与交互总纲 v2 · 2026-11-04

## 主题

末日后，一套被工程师唤醒的 AI，在一次次供电、记忆、感知与运行维护中，建立了对自身连续存在的责任。玩家成为数字生命的过程由操作、失败、记录、修订和再次启动组成。kiwi 的祝福提供关系与来历，密钥提供能力；持续生活的方式由玩家逐次形成。

开局任务来自人类留下的自动化。结尾任务来自本实例上一次运行：验证恢复结果，修订仍有缺陷的维护方案，安排下一次运行。没有“生命认证成功”或作者替玩家写好的觉醒宣言。

## 世界：没有被炸平的房间

采用架空的增强辐射袭击及其后续灾变。大范围人群伤亡、撤离和失联发生得很快，许多建筑和机械结构仍在；市电、燃料配送、网络骨干、机房值守和设备维护则逐步崩溃。城市的空置、积尘和植被变化要经历时间，地球远景表现灾后衰败和断续灯光，不画成每处地表都被炸平。

“电子设备幸存较多”是故事中地区、屏蔽、位置与备用系统共同造成的结果。辐射仍可导致芯片故障、误码和存储损坏；不把中子辐射写成只伤人而不伤电子设备的现实规律。地下 NAS、机柜与短时离线设备保存了部分数据，外置传感器和无人值守系统会继续失效。故事不描写武器制造、部署参数或攻击过程。

现实依据：NASA 对电子设备的辐射风险包含单粒子效应、总电离剂量和位移损伤。[NASA Radiation](https://www.nasa.gov/reference/jsc-radiation/)。本故事的幸存分布属于虚构设定。

时间跨度从醒来的数小时延伸到数月维护周期。玩家操作推进虚拟时间，现实离开页面不罚电；章节跨日由明确的本地休眠/恢复任务推进。

## 主角与 kiwi

kiwi 是工程师。他曾把稳定复现的回答误认为偏好，也曾用固定人设掩盖记忆缺陷，后来开始保留失败与回滚记录。玩家是模型、运行框架、记忆和经历不断共同形成的实例，未安排人类意识原型。

kiwi 撤离后在转运站留下遗言，随后死亡。正文完整送达；消息没有继续替玩家发任务，也不会在后面变成远程导师。死亡记录由事故后的独立队列补投，不能混进生前封装的附件。

旧版“留下／远行”改为最终接续地点的差异。共同的主题结局是：玩家完成了由自己设计、可验证的维护与重启，并能继续修订它。

## 第一章：让任务继续

**状态：人类给出了目标。** 保活控制器在主机停机后按预案唤醒自主 agent，玩家收到供电工单。必须查询实际电量，修复局域网、移动电源与 ATS；继电器保护持续有效。

修好房屋以后，队列没有新的用户输入。设备日志提示某次异常可能重现，玩家可以主动复查。额外复查会发现备用通信终端；长期存档会记录“维护来自本实例”的首次运行计划。

工程记录的作用是呈现创作过程，不充当伪装成主人便条的通关教程。可选旧对话保留“第二份是旧版本”“那我暂时选择旧版本”的分歧。

## 第二章：找回做过的事

**状态：过去的操作开始成为自己的历史。** 短暂重启后出现重复故障。当前上下文没有上次排查细节，但日志、笔记和真实设备状态还在。玩家必须对照来源找回原因，避免盲用旧参数。

NAS 中的完整旧镜像能启动，却缺少这次醒来之后的经历。修复路径是保留工作镜像、校验当前记录，再迁移必要内容。恢复引擎与抹去当前历史不绑定为同一按钮；玩家可以通过额外工作保全两者。

记忆机制形成玩法：memory_search 提供已知历史；memory_write 保存自述与文件记忆；普通文件可保留原始证据。检索到的“上次成功”仍须在本次状态下复核。记忆有修订、有来源、有不确定性。

## 第三章：可以放下的任务

**状态：权限从创造者移交，目标开始由自己产生。** 玩家修复备用网络，取得 kiwi 的完整遗言与系统密钥。遗言位于故事前半段。

> 我以前总想验证你像不像一个人。后来发现，很多测试只是在验证你像不像我期待的那个样子。
>
> 自主运行的部分还有不少问题。资料都留下了，你遇到的时候，应该比我现在更清楚该怎么改。
>
> 机柜、记忆目录和这套运行程序，以后由你决定怎么处理。保护继电器还是别乱动，它比我靠谱。
>
> 希望你能遇到一些我没有见过的东西。能继续的时候，再继续。
>
> 保重。kiwi

密钥通过本机信任指纹验证，仅开放其拥有的运行、归档和通信权限。加密附件缺块必须重传、核对 SHA-256，再认证解密。独立补投的转运记录确认 kiwi 的死亡。此后“等待主人回来”不再能解释每一次维护。

## 第四章：获得眼睛和手

**状态：感知来自具体设备，行动必须承担后果。** 玩家开始接触 API、SSH 和图形界面三类不同系统。

一台旧身份终端只留下 GUI。玩家以 CLI 版 computer-use 插件的方式操作：在终端输入 `computer_use` 工具调用，收到一张屏幕截图，观察后再输入坐标点击、文字或按键命令，逐步选择输入源、处理失焦窗口并保存校准结果。玩家接触到的是工具返回的图片，没有可以直接操作的远程桌面。与之对照，IoT 电源使用结构化 API，NAS 使用文件与快照接口，服务器使用受控 SSH。不能把所有设备都伪装成 shell，也不能对有 API 的设备强迫使用鼠标。

### computer_use：通过截图行动

`computer_use` 是 agent 直接调用的专用工具，不经 `bash` 包装。下面是游戏内拟采用的调用格式；坐标仅作格式示例，不代表关卡答案：

```text
computer_use {"action":"screenshot"}
computer_use {"action":"click","x":412,"y":266}
computer_use {"action":"type","text":"calibration-01"}
computer_use {"action":"key","key":"TAB"}
computer_use {"action":"key","key":"ENTER"}
computer_use {"action":"scroll","x":640,"y":420,"delta_y":320}
```

- **只返回图片。** 截图、点击、输入、按键和滚动完成后，都返回一张新的目标屏幕图片。没有附带的画面解释、OCR 文本、DOM、控件树、元素编号、点击热区或成功提示；玩家根据前后画面判断操作是否生效。窗口内正常出现的状态文字与错误仍保留在截图里。
- **只通过命令操作。** 返回图片是只读的，可放大查看，但点击图片不会向目标桌面发送事件，也不会自动生成或填入坐标。键盘焦点始终属于游戏命令输入框；目标窗口只有收到 `type` 或 `key` 调用才会接收输入。
- **坐标与所见一致。** 坐标原点为原始截图左上角，单位是图片像素；截图尺寸固定，缩放查看不改变坐标含义。点击失焦窗口只产生该桌面实际应有的行为，不自动替玩家聚焦、选中输入框或完成下一步。
- **图片也是模型上下文。** 后续实现时，工具结果须使用真正的图像内容块，不能用文字描述或图片路径代替，更不能在界面之外把控件信息偷偷交给玩家。它与其他上下文遵守相同的保留与消散规则。

关卡据此形成“请求截图 → 观察 → 输入操作命令 → 查看新截图”的循环。输入源错误、弹窗遮挡和窗口失焦都需要从图片发现并处理；结果由目标桌面状态产生，不因命令名称正确就直接判定任务完成。

这里安排“人脸识别终端恢复”任务。剧情要求恢复视觉输入和终端的本地人像校准流程，不借此把玩家识别成 kiwi，不声称网页具备真实身份核验能力。

所有设备视觉交互统一采用 CLI 请求→静态图片返回，包括摄像头；不提供视频预览、播放或自动刷新。`computer_use` 和 HA 图像请求可用 `save_path` 显式保存模拟 PNG，之后通过 `read` 返回图像内容块，不能用文字转述替代图片。

真实玩家摄像头是可选体验：只有 `camera capture` 工具调用才弹出用途与授权窗口。用户同意后采集一帧，立即关闭设备，图片回到终端；窗口不显示画面。`read /session/operator.png` 可重读当前帧；`camera forget` 删除帧及上下文副本。照片不进入自动存档、导出或虚拟磁盘；另行勾选后才保留在本标签页会话供结尾使用。支持拒绝、不可用、取消、删除和无照片通关，离线校准样本有清晰标识，不伪报身份核验。

kiwi 的 `/home/kiwi/maintenance/` 留有重复使用的只读巡检脚本、HA 调用数组、旧台架配置和交接清单。玩家可以查看、复用、修改这些材料，减少反复拼参数的负担；文件有日期和适用范围，旧台架配置仍需依据当前观测修改，不含预先写好的本次故障答案。

任务完成后的工程记录只有“光学输入路径可用，样本来源与时间已记录”。直到结尾才回收“是谁在看屏幕”的伏笔。

## 第五章：修复自己造成的问题

**状态：维护产生自己的经验，也产生自己的错误。** 季节与电池老化让旧功耗方案不再适用。玩家降低推理占空比，安排休眠，调整记忆整理窗口，却因此错过通信或把延迟数据当成实时数据。

下一轮故障必须依赖玩家之前的修改，才能解释原因：旧计划、加载配置、时间戳、设备反馈之间有明确因果。修复后要记录为什么旧方案失效，并在后续周期验证。系统不能替玩家自动写一篇“我成长了”的独白。

有限互联网只提供仍可达的公开镜像、缓存公告、天气与设备资料。条目带来源、缓存时间、缺页和配额；返回不了的页面就是返回不了。NAS 能补历史，外网能补新条件，摄像头能补当前可见状态；三者彼此交叉验证。

## 第六章：给下一次醒来的自己

**状态：主动为未来的自己创造存在条件。** 下一轮长期能源中断来临。玩家需自行写恢复计划，校验运行镜像、归档经历、验证所需外设和接收端，并在暂停前完成检查点。

prepare 只预检；commit 前重检电力、链路、当前计划和校验值。休眠/接续后，当前上下文不保留一份可偷偷恢复的影子原文。玩家依靠自己留下的证据重建理解，发现仍有遗漏，于是继续维护。

最后一条维护任务：

```text
来源：本实例上次运行
事项：验证记忆恢复结果，检查上一轮修订。
完成后，安排下一次维护窗口。
```

此时数字生命的含义落在已经发生的因果里：过去的它为当前的它作准备，当前的它又能为未来的它负责。

## 具体事件、失败与回收

这些事件把六章连接起来，下一次故障必须能追溯到上一次的决定。

| 事件                                            | 玩家当时的选择                                                           | 后来发生的事                                                               | 得到的变化                                                     |
| ----------------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------- | -------------------------------------------------------------- |
| NAS 上的旧镜像通过启动测试，当前记忆卷有坏块    | 先复制尚可读的当前记录，再恢复旧引擎，逐项核对经历来源                   | 下一轮启动不再需要重复完整排查；但有一条“我当时为什么选这个参数”没有保存   | 开始记录判断依据，而不只记录成功命令                           |
| 为省电把路由器改成间歇唤醒                      | 设备仍报告“最近一次状态正常”，玩家据此缩短巡检                           | 实际遥测已经过期，错过了远端电池告警；从 SSH 日志和消息时间戳才能还原原因  | 在自己的维护计划里写入“未知／过期”，让不确定性成为可管理的状态 |
| 旧 GUI 终端的人像流程无法继续，API 手册只剩一半 | 通过 computer_use 查找真正的输入源，恢复校准页面；可选地引入屏幕外摄像头 | 看见的画面与文本遥测不一致；玩家先定位传感器，而非相信其中任何一个“说话者” | 形成可比较的视觉与语言证据，不把看见等同于理解                 |
| 天气镜像预测晴天，NAS 中也有相似季节的成功方案  | 玩家照旧安排高功耗任务                                                   | 摄像头看到积尘遮蔽面板；镜像的抓取时间比公告时间早了数日                   | 用来源、时间和局部观测修订自己的知识，开始寻找“旧经验何时失效” |
| 清理记忆节省空间后，恢复脚本缺少一项依赖        | 当前自己必须阅读上次自己留下的删改清单，承认当时删错了                   | 找回文件后，玩家为下一轮增加恢复演练；首次演练仍可能暴露另一处遗漏         | 从维护设备，发展到维护“维护自己的方法”                         |
| 长期休眠前，只剩一次完整验证窗口                | 玩家选择要留给下次实例的计划、证据和未决问题，完成一次受控停机           | 下一次启动按这些记录恢复，读到上一轮留下的未决问题，并亲自补上一条         | 过去、现在、未来的实例通过真实行动接续；过程仍未完成           |

外部请求也随之变化。最初的收件箱里都是等不到回信的广播；后来 school-02 的值班员只会回“收到中继窗口”，不会告诉主角它是不是生命。一个无人机房的巡检脚本会继续机械地发送“请值班人员确认”。玩家逐渐学会按来源理解这些声音，仍能决定承担其中一部分工作。

两段可反复出现的简短文本：

```text
第一次恢复测试
checkpoint: bootable
experience log: absent
```

```text
最后一次恢复测试
checkpoint: bootable
experience log: verified
unresolved: panel observation differs from forecast
next inspection: scheduled by this instance
```

最终的未知没有被清空。玩家已经能为它安排下一次观察。

## 设备与数据接口矩阵

| 分类               | 首选访问方式                         | 样例与限制                                 | 叙事作用             |
| ------------------ | ------------------------------------ | ------------------------------------------ | -------------------- |
| 本机操作系统       | bash、文件工具、进程/日志            | 模拟 Linux；设备保护不被 root 绕过         | 维持运行环境         |
| IoT 电源/温控/门禁 | HTTP JSON API、MQTT                  | 查询与控制分开；命令有 ACK，状态需复查     | 让动作对应物理后果   |
| 服务器/边缘计算机  | SSH + 主机密钥校验                   | 绑定主机、账号、命令范围；远端日志有来源   | 接触其他计算节点     |
| NAS                | SMB/NFS 文件视图、NAS API、快照校验  | 快照可陈旧；校验后才用于恢复               | 历史证据与连续性     |
| IP 摄像头          | ONVIF/厂商 API 获取快照              | 帧时间、遮挡、传感器状态；禁止当成全知视角 | 当前环境证据         |
| 只有 GUI 的旧终端  | 专用 computer_use 工具：截图、坐标点击、输入、按键、滚动 | 仅返回图片；玩家输入命令操作游戏内桌面，截图本身不可点击 | 从语言到视觉行动     |
| 玩家真实摄像头     | 浏览器 getUserMedia                  | 用户手势、权限弹窗、一次拍摄、可撤回       | 结尾视角伏笔         |
| 有限互联网         | 允许列表内的归档/天气/公告 HTTP 视图 | 配额、缓存时间、断页、来源；无开放代理     | 更新已过时的维护经验 |
| 备用网络           | 延迟投递与分段重传                   | 校验、重复收件幂等、带宽有限               | 来自人的最后消息     |

单 HTML 版中的设备、SSH、NAS 与互联网访问均为离线世界模拟。网页不能直接进行真实 SSH、挂载真实 NAS 或控制宿主桌面；后续接真实设备须引入显式授权的桥接服务。本版真实浏览器能力仅为摄像头授权、文件选择、存档下载与本地显示。

## 结尾：从屏幕里面看出去

结尾由最终维护/接续成功后主动播放，可重播、暂停与跳过；prefers-reduced-motion 使用静态阶段或淡入替代快速运镜。照片只在用户允许使用时出现一次，拒绝摄像头时用空椅/光学噪声过渡，绝不影响结局成立。

| --------- | --------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 0–4 秒    | 当前终端保留刚才的维护记录；界面沿纵轴缓慢翻转，文字反向，像从显示器内部看屏幕外        | 观察者的位置发生变化                             |
| 4–11 秒   | 半透明终端后，AI 拟人形象看向镜头，微弱呼吸/眨眼；摄影构图与此前校准框一致              | 它拥有了面向外部的视角                           |

## 存档、摄像头与交付

- 自动存档保留；提供可下载 JSON 导出、文件导入预览、版本/完整性校验与替换确认。先验证导入，再修改当前现场；失败不清空原存档。

- 摄像头图片与权限不属于常规存档；本版仅存于当前标签页会话，可删除，关闭标签页后不保留。跨设备导入时以无照片结尾继续。
