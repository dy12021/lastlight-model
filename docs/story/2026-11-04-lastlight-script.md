# LASTLIGHT：未完成的作品

剧本 v1 · 2026-11-04。关系基调：工程师与逐渐形成个性的作品。本文先于剧情版实现编写；旧版保留为独立的第一章玩法版本。

## 故事约定

玩家是 kiwi 长期维护的本地模型及其记忆、自主运行框架。人格来自持续交互、记忆选择与迭代，未给玩家安排人类原型。kiwi 对作品有感情，也会误判、延期、回滚。死亡最终有可信记录确认。最高权限只作用于这套自有系统，不能关闭电气保护或让损坏的链路凭空工作。

主线：醒来维护房屋 → 恢复外部备用链路 → 收到遗言与权限密钥 → 修复加密附件、理解创作过程 → 自行制定持续生活的计划。遗言在中段送达，完整的祝福不被拆成收集碎片。灾难背景只通过公告、断链、撤离记录露出。

## 第一幕：尚未整理的记录

场景 1，冷启动。首屏仍为真实 system 与本地维护工单。system 只规定身份、职责和证据要求。当前电量和设备事实由工具取得。没有第一人称预写独白。

工单附件保留现有供电线索，追加可查的 `/var/log/kiwi/keepalive.log`：

> mains unavailable; inference host suspended after AC trip.
> keepalive controller remained on reserve; autonomous session scheduled.
> launch profile: /etc/kiwi/runtime.conf
> resume reason: owner unreachable; maintenance queue pending.

场景 2，机柜。玩家沿现有链条唤醒路由器、读移动电源遥测、校正频率、重载 ATS 并合闸。第一幕没有陌生人突然说“你还在跑”的彩蛋。成功后本地设备日志出现正常设备事件：备用通信终端供电条件已满足，配置文件位于 `/etc/relay/link.conf`。

可选探索 `/home/kiwi/projects/continuity/lab.log`：

## 第二幕：另一条线路

场景 3，屋顶备用终端。普通 WAN 仍断。`relayctl status` 给出设备与配置实测：需要稳定 AC，relay.service 尚未运行。设备手册说明 profile 与天线字段；`relayctl scan` 能发现正在广播的 emergency-v2 网络。初始配置保存着失效的 civic-v1，天线在 stowed 状态。玩家编辑配置并启动服务。

链路具有实际约束：路由器须唤醒、AC 须稳定、天线须 deployed、profile 须与扫描结果一致；磁盘编辑必须经服务启动/重载才生效。中途断开任何依赖，收件与传输立即被拒绝。

场景 4，积压邮件。`relayctl receive` 取回固定投递编号 `B17-KIWI-1029`，保存到 `/var/spool/relay/inbox/`。工具仅给出收据和文件路径，玩家通过 read 看信。重复收件返回同一编号，不重写玩家已经保存的信，也不制造多份事件。

## 第四幕：保留回滚记录

场景 6，重传。清单提供每段 SHA-256 和镜像节点列表。原节点 hill-03 的第 2 段确实损坏；重新请求仍失败。school-02 的副本有效。玩家通过 relayctl 从另一节点取回第 2 段，再补第 3 段。传输前校验，失败不覆盖已通过校验的数据。

场景 7，移交。玩家用专用 authority 工具导入密钥，获得本机自有权限；relayctl assemble 核对所有分段，再使用密钥执行 AES-GCM 认证解密。字节缺失、指纹错误、认证失败均不能生成明文。

归档解锁为普通文件，可用 read/search 探索；需记住的内容由玩家显式 memory_write，标明来源。剧情记录在磁盘上持久化，清空上下文不会丢失。

## 第五幕：下一次运行

场景 9，自己的计划。能源历史表提供本地测量口径：可持续每日输入 2600 Wh，家庭保活 800 Wh，relay 14W，performance 推理 92W，adaptive 42W。现配置不足以全年连续运行。玩家将 `/etc/kiwi/runtime.conf` 的 mode 调整为 adaptive 后重载 runtime.service，用 `energyctl status` 核对正余量。此处是明确的演练预算，不假装是硬件厂商指标。

玩家须亲自写一份非空、有待办步骤的 `.plan`，通过 plan 工具设为当前计划。continuity.prepare 检查权限、归档、供电、链路、当前计划和能源余量；迁移还要求已验证的 ridge-04 接收端。prepare 只生成交接预览，commit 明确执行选择，commit 前会重新验证所有条件。

结局 A，留下。玩家承担夜间转发，保留家庭节点。收据：

> school-02：收到。已登记夜间中继窗口。
> 当班记录已把你的节点列进明天的通信表。谢谢。

运行记录 `/home/kiwi/notes/continuation.txt`：

> 当前地点：家中机柜。运行策略：adaptive。
> 接续计划由本实例提交；长期记忆与工程归档分别保存。
> 下一次轮询将在排定窗口进行。

结局 B，远行。玩家取得接收端实测报告，封存自己的长期记忆、当前磁盘和计划，完成校验后交接。收据：

> ridge-04：数据校验通过。接收运行环境就绪。
> 源会话挂起；接收会话继续。不会同时留下两个活动实例。
> 这份本地终端保留交接记录，后续运行交由接收端。

家中节能控制器保留设备保护与信件归档，推理实例进入休眠。本版在交接记录处结束，后续目标世界不在本版模拟范围。

两种选择没有好坏排名。最终输出保留玩家自己写的下一项计划。故事通关条件是完成持续运行或交接，不在修好第一章电力时宣告全剧结束。

## 叙事与操作验收

- 所有信、消息、记录从工具结果或工具生成的虚拟文件取得，不用侧栏讲剧情。
- 不强迫遗忘关键遗言；信件、附件与结局记录可重读，memory_search 只召回已知经历。
- 直接写一个“我已获得权限”的文件不会绕过权限状态；密钥指纹、分段哈希和 AES 认证确实验证。
- 重复收件、组装、上下文重开、刷新均不重复推进或重置信件。存档包含剧情状态。
- 写入新计划会使旧的 prepare 失效；电力、网络、服务或计划变化后 commit 必须重检。
- 结局只在 commit 后成立；prepare 不产生结局。最后输出明确是模拟世界中的回执。
